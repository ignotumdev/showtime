Plan 01

Shows Backend

Add the first backend foundation for show files in Showtime: shared Effect schemas and branded types, an IDs module, show file persistence, and Electron main-process startup discovery.

Scope

Backend only. No renderer UI or user workflow yet.

First Milestone

Log discovered .showtime files from HOME/.showtime/shows.

Data Model

Field Type Notes
config.version literal "dev" No migrations during development. Old files can be discarded.
config.id branded ShowId Generated as show_ plus 16 chars from 0123456789abcdefghijklmnopqrstuvwxyz.
config.name string User-facing show name. Validation should reject empty or whitespace-only values.
config.createdAt Effect DateTime schema Use Effect-native DateTime encoding in contracts so date handling stays explicit and consistent.
config.updatedAt Effect DateTime schema Must change on every show file update, including config-only updates.

Implementation Sequence

  1. 1. Define contracts in packages/contracts

    Add Effect Schema definitions and exported TypeScript types for show IDs, the dev config version, show config, and the full show file document. Keep the contracts package runtime-safe so every backend read validates unknown JSON before it is trusted. Use Effect-native DateTime schemas for createdAt and updatedAt.

    • Use branded schemas for entity IDs, with a specific ShowId brand.
    • Validate the show_ prefix and the 16-character custom alphabet suffix.
    • Export constructors or parser helpers only if they reduce duplication for backend services.

  2. 2. Add an Effect-native IDs module

    Create apps/desktop/electron/backend/ids/Ids.ts to own ID generation. It should use nanoid with the alphabet 0123456789abcdefghijklmnopqrstuvwxyz and a length of 16, then prepend the entity prefix such as show_.

    • Expose a method like makeShowId returning the branded ShowId.
    • Keep raw string generation private to the service.
    • Use Effect service/layer patterns, but do not suffix module files with Service.
    • Add nanoid to the desktop package if it is not already present.

  3. 3. Create show storage path helpers

    Centralize filesystem paths for show storage in shows/ShowPaths.ts. Resolve the base directory as HOME/.showtime/shows in the main process, using Effect Platform and @effect/platform-node wherever possible instead of direct Node filesystem calls.

    • Use os.homedir() instead of renderer-provided paths.
    • Keep the .showtime extension in one shared constant.
    • Create HOME/.showtime/shows on first-run discovery so startup behavior is predictable.
    • Use the filename format show-name-id.showtime for new show files, with sanitization for filesystem safety.

  4. 4. Build show file persistence

    Add shows/ShowFile.ts as the Effect module responsible for reading, validating, updating, and writing a show JSON file. Even if the first runnable behavior only logs discovered files, design this module now so later UI actions do not duplicate persistence logic.

    • Use Effect Platform filesystem APIs and @effect/platform-node runtime layers where they fit the task.
    • Read JSON with schema validation before modification.
    • Write JSON deterministically with stable formatting.
    • Always set updatedAt during updates.
    • Prefer atomic write behavior: write to a temporary file in the same directory, then rename.
    • Represent filesystem and parse failures as typed errors instead of thrown exceptions leaking across service boundaries.

  5. 5. Add show discovery

    Implement discovery in shows/ShowDiscovery.ts for all files ending in .showtime inside HOME/.showtime/shows. For the first backend milestone, discovery should log every candidate file it finds from Electron main.

    • Create the show directory if it does not exist, then log an empty result if no files are present.
    • Filter out directories and non-.showtime files.
    • Log absolute paths for diagnostics.
    • Optionally validate each discovered JSON file after the initial logging milestone is working.

  6. 6. Wire backend startup into Electron main

    Import a small backend entrypoint from apps/desktop/electron/backend and run it from app.whenReady() before or alongside window creation. Keep the main file focused on Electron lifecycle code.

    • Build a composed Effect layer for IDs, show paths, show files, discovery, and the Node platform layer.
    • Run startup discovery with Effect.runPromise or the repo-preferred Effect runtime pattern.
    • Catch and log startup backend failures without preventing the window from opening during this early milestone.

Acceptance Criteria

  • Contracts exports include branded show ID types and Effect schemas for the dev show file format.
  • Contracts use Effect-native DateTime schemas for createdAt and updatedAt.
  • The backend folder exists under apps/desktop/electron/backend with per-type folders such as ids/Ids.ts and shows/ShowFile.ts, and is imported by Electron main.
  • Starting the desktop app logs discovered absolute paths for every .showtime file in HOME/.showtime/shows.
  • A missing HOME/.showtime/shows directory is created during startup discovery and does not crash startup.
  • New show files use the filename format show-name-id.showtime.
  • Show updates go through one Effect service and always refresh updatedAt.
  • TypeScript build passes for contracts and desktop.

Testing Plan

Add unit tests for ID format validation and schema decoding, especially invalid prefixes, invalid alphabet characters, and wrong suffix length.

Add backend service tests with a temporary HOME or injected base path so discovery can verify missing directory, empty directory, mixed files, and valid .showtime files.

Add update-service tests confirming stable JSON output and changed updatedAt.

Use Vite Plus for tests. vp test is built on Vitest, does not run in watch mode by default, and test configuration should live in the test block of vite.config.ts rather than a separate Vitest config.

Run pnpm ready or the workspace equivalent after implementation.

Resolved Decisions

  • First-run discovery creates HOME/.showtime/shows.
  • New show filenames use show-name-id.showtime.
  • Dates use Effect-native DateTime schemas in packages/contracts.
  • The Electron backend uses per-type folders and avoids Service suffixes in file names.
  • Filesystem work should prefer Effect Platform and @effect/platform-node.
